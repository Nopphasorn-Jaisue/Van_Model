**โฟลเดอร์ซอร์สโค้ด:** `soure_code/`  
**กิตฮับรีโพซิทอรี (GitHub Repository):** https://github.com/Nopphasorn-Jaisue/Van_Model.git  
**ประกอบด้วย 2 เวอร์ชัน:**
1. **เว็บแอปพลิเคชันรุ่นภาษาไทย (`web_app_th.py`)** — พอร์ตเริ่มต้น `8080`
2. **เว็บแอปพลิเคชันรุ่นภาษาอังกฤษ (`web_app_en.py`)** — พอร์ตเริ่มต้น `8081`
3. **เอนจินคณิตศาสตร์หลัก (`van_allocation_engine.py`)** — โมเดล MILP (PuLP + COIN-OR CBC) พร้อมระบบตรวจสอบกติกาความจุของเว็บ (`TC66–TC69`) และกฎความปลอดภัย HOS (14 ชม./วัน, 72 ชม./14 วัน, เวลาพัก 10 ชม.)

## 2. ความต้องการของระบบและการติดตั้ง (System Requirements & Installation)

### 2.1 ความต้องการขั้นต่ำของระบบ
- **ระบบปฏิบัติการ:** Windows 10/11, macOS หรือ Linux (Ubuntu 20.04 ขึ้นไป)
- **Python:** เวอร์ชัน 3.9 – 3.12 (แนะนำ Python 3.11)
- **เว็บเบราว์เซอร์:** Google Chrome, Microsoft Edge, Firefox หรือ Safari
- **ตัวแก้ปัญหาคณิตศาสตร์ (MILP Solver):** **COIN-OR CBC** ซึ่งติดตั้งมาพร้อมกับไลบรารี `pulp` อัตโนมัติ (โอเพนซอร์ส 100% ไม่ต้องใช้ไลเซนส์เชิงพาณิชย์)

### 2.2 ขั้นตอนการดาวน์โหลดและติดตั้งจาก GitHub
เปิดโปรแกรม PowerShell หรือ Terminal แล้วรันคำสั่งต่อไปนี้ตามลำดับ:

```powershell
# 1. โคลนโปรเจกต์จาก GitHub Repository
git clone https://github.com/Nopphasorn-Jaisue/Van_Model.git
cd Van_Model/soure_code

# 2. (แนะนำ) สร้างและเปิดใช้งานสภาพแวดล้อมเสมือน (Virtual Environment)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3. ติดตั้งไลบรารี Python ที่จำเป็นทั้งหมด
pip install -r requirements.txt
```

## 4. คู่มือการใช้งานฟีเจอร์บนหน้าเว็บแอปพลิเคชัน

หน้าจอของระบบเว็บแบ่งออกเป็น 3 ส่วนหลักเพื่อให้ผู้บริหารและเจ้าหน้าที่ยานพาหนะใช้งานได้ง่าย:

### ส่วนที่ 1: การตั้งค่านโยบายมหาวิทยาลัยและเกณฑ์ความปลอดภัย (HOS Parameters)
ผู้ใช้งานสามารถปรับพารามิเตอร์ให้ตรงกับบริบทของมหาวิทยาลัยตนเองและกดปุ่ม **"🚀 รันจัดสรรรถตู้ด้วยโมเดล MILP"** เพื่อเปรียบเทียบผลลัพธ์ได้ทันที:
1. **ความจุรถตู้มาตรฐาน (ที่นั่ง/คัน):** ค่าเริ่มต้น `11` ที่นั่ง (สามารถปรับเป็น `12`, `13` หรือ `20` ที่นั่งตามขนาดรถของมหาวิทยาลัย)
2. **เพดานทำงานรายวันสูงสุด (ชม./วัน):** ค่าเริ่มต้น `14.0` ชั่วโมง/วัน
3. **เพดานสะสม 14 วันสูงสุด (ชม./14 วัน):** ค่าเริ่มต้น `72.0` ชั่วโมง/14 วัน (ตามเกณฑ์เวลาปฏิบัติงานและล่วงเวลาภาครัฐ เฉลี่ย 36 ชม./สัปดาห์)
4. **เวลาพักขั้นต่ำระหว่างทริป (ชม.):** ค่าเริ่มต้น `10.0` ชั่วโมงต่อเนื่อง
5. **นโยบายการยืมรถข้ามคณะ (Cross-Faculty Resource Pooling):**
   - เมื่อเลือก **"✅ เปิดใช้งานการแชร์รถข้ามคณะ (Shared Pool)"**: ระบบจะอนุญาตให้ยืมรถว่างจากคณะพันธมิตร (เช่น ยืมรถคณะ SCI ไปช่วยงาน ICT และ SEEN จำนวน 8 เที่ยว ทำให้จัดสรรสำเร็จ **9/10 คำขอ [90.0%]** หรือ **62/69 คน [89.9%]**)
   - เมื่อเลือก **"🔒 ปิดการแชร์รถ (Siloed Policy)"**: ระบบจะบังคับใช้เฉพาะรถของคณะตนเอง ทำให้จัดสรรสำเร็จลดลงเหลือเพียง **1/10 คำขอ (10.0%)** ซึ่งแสดงให้เห็นประโยชน์ของการใช้รถร่วมกันข้ามคณะอย่างชัดเจน

### ส่วนที่ 2: การเพิ่มคำขอจองรถตู้ใหม่และระบบตรวจสอบกติกาความจุของเว็บ (`TC66–TC69`)
1. กรอก **รหัสคำขอ**, เลือก **คณะผู้ยื่นคำขอ** (`ICT`, `SCI`, `SEEN`), **จำนวนผู้โดยสาร**, **จำนวนรถที่ขอ**, **ขอบเขตการเดินทาง** (ต่างจังหวัด / ในจังหวัด) และ **ชั่วโมงปฏิบัติงานของทริป**
2. กดปุ่ม **"+ ตรวจสอบกติกาเว็บและเพิ่มลงในคิว"**
3. ระบบจะตรวจสอบกติกาความจุของเว็บโดยอัตโนมัติ:
   $$\text{จำนวนผู้โดยสาร } (P_r) \le \text{ความจุรถต่อคัน } (C_v) \times \text{จำนวนรถที่ขอ } (K_r)$$
   - หากขอรถ 1 คัน แต่กรอกผู้โดยสาร 15 คน (หรือขอรถ 2 คัน แต่กรอกผู้โดยสาร 23 คน เกินเพดาน $11 \times 2 = 22$ ที่นั่งตามกรณีทดสอบ `TC68`) ระบบเว็บจะบล็อกคำขอและแจ้งเตือน **`INVALID_INPUT`** ทันที
   - หากผ่านเกณฑ์ ระบบจะเพิ่มคำขอลงในคิวและสั่งรันตัวแก้ปัญหา MILP ใหม่โดยอัตโนมัติ

### ส่วนที่ 3: การ์ดสรุปตัวชี้วัด (KPI Cards) และตารางผลลัพธ์รายคำขอ
- **การ์ดสรุปตัวชี้วัด 5 ด้าน:** แสดงอัตราจัดสรรคำขอสำเร็จ, จำนวนผู้โดยสารที่รองรับ, จำนวนเที่ยวที่ยืมรถข้ามคณะ, จำนวนการละเมิดกฎความปลอดภัย HOS (`0 ครั้ง`) และเวลาประมวลผลของตัวแก้ปัญหา CBC
- **ตารางผลลัพธ์รายคำขอ:** แสดงรหัสคำขอ, คณะ, จำนวนผู้โดยสาร, ขอบเขต, วัน-เวลาเดินทาง, ทะเบียนรถและรหัสคนขับที่ได้รับมอบหมาย, ป้ายสถานะการยืมข้ามคณะ และเหตุผลประกอบการจัดสรรหรือปฏิเสธอย่างละเอียด (ตรงตามตารางที่ 6 ในบทความวิจัยทุกประการ)

## 5. การใช้งานผ่าน Command Line (CLI) และ REST API

นอกจากการใช้งานผ่านหน้าเว็บเบราว์เซอร์แล้ว นักวิจัยและผู้พัฒนาระบบยังสามารถรันผ่าน CLI หรือเชื่อมต่อ REST API ได้โดยตรง:

### 5.1 การรันผ่าน Command Line (`van_allocation_engine.py`)
```powershell
# แสดงผลการจัดสรรคิวคำขอจริง 10 รายการในรูปแบบ JSON บนหน้าจอ Terminal
python van_allocation_engine.py --mode demo

# แสดงตารางสรุปผลการทดลองเชิงประจักษ์ v6 ทั้งหมดจากโฟลเดอร์ raw_output/
python van_allocation_engine.py --mode summary
```

### 5.2 รายการจุดเชื่อมต่อ REST API ของเว็บเซิร์ฟเวอร์
- `GET /api/preset` — ดึงข้อมูลคิวคำขอรออนุมัติจริง 10 รายการ ข้อมูลรถตู้ คนขับ และตารางงานคงที่เดิม (`FixedBusyBlocks`)
- `POST /api/validate` — ตรวจสอบความถูกต้องของจำนวนผู้โดยสารเทียบกับจำนวนรถที่ขอ (`{"pax": 15, "requested_vans": 2, "van_capacity": 11}`)
- `POST /api/solve` — ส่งชุดคำขอและพารามิเตอร์ `config` เข้าสู่ตัวแก้ปัญหา MILP และรับผลการจัดสรรกลับในรูปแบบ JSON
